# WB Repricer

Утренняя страница решений по ценам Wildberries. Сама цены в кабинет **не пишет** – считает рекомендации, менеджер вписывает их вручную и отмечает «Поставил» / «Своя цена» / «Не ставлю».

В комплекте две кампании на одном движке:

1. **Подъём цен** – плавный рост к цели с защитой потока заказов.
2. **Цены под цель** (`op/`) – решения от остатка в днях и целевой операционной прибыли.

Нужны `python3` и `curl`. Внешних pip-зависимостей нет.

## Быстрый старт

```bash
git clone <этот-репозиторий> wb-repricer
cd wb-repricer
cp .env.example .env && chmod 600 .env
# впишите WB_TOKEN и SITE_DIR

cp config.example.json config.json
cp examples/plan.example.json plan.json
cp examples/state.example.json state.json
mkdir -p op
cp examples/op-plan.example.json op/plan.json
cp examples/state.example.json op/state.json

# первичная сборка плана по кабинету (необязательно, если plan.json уже свой)
python3 wb_setup.py --token "$WB_TOKEN"

./run.sh
```

Страница появится в `SITE_DIR` / `PAGE_NAME`.

Кампания «цены под цель»:

```bash
./op/run.sh
```

## Отметки со страницы

```bash
python3 control/feedback_server.py
```

Проксируйте на него `/wb-feedback` (или `/run/feedback`). Ключ – `FB_KEY` в `.env`, страница шлёт заголовок `X-FB-Key`.

## Что не входит в репозиторий

- токены, `.env`, пароли;
- живые `plan.json` / `state.json` / история цен / заказы / отметки;
- ваши Google-таблицы и финансовая база.

Примеры лежат в `examples/` и `*.example*`.

## Важно

- Токен WB – **только чтение**. Запросов на запись цен в коде нет.
- Повторный утренний прогон в тот же день после подъёма блокируется (`./run.sh --force` – осознанный обход).
- Колонки в таблицах ищутся **по названию**, не по букве.
- Остаток WB – строка «Склад WB РФ» отчёта `warehouse_remains`. Разбивку по складам из API не используйте.
